## Errores corregidos

- Cruces espaciales multiplicaban IDs y podían contaminar entrenamiento/validación.
  Ahora se colapsan por muestra y se conservan las alternativas de atributos ambiguos.
- La carga rechaza IDs duplicados y resuelve el dataset al usarlo, evitando rutas
  elegidas antes de que una etapa del pipeline generara el archivo.
- La validación agrupa réplicas y reserva un holdout; los folds de CV usan solo
  la partición de entrenamiento. El benchmark ya no entrena dos veces cada fold
  para obtener etiquetas y probabilidades.
- Distancias con coordenadas desconocidas e índices con denominadores ausentes
  conservan NaN; no se interpretan como cero ni como una posición en la fosa.
- La imputación mantiene las columnas vacías para evitar desalinear el esquema.
- Entradas ausentes producen un error real; no un falso éxito del pipeline.
- Los modelos exportados registran hashes del dataset y versiones de librerías.
  El esquema PetroPyQAPF se genera junto con los modelos y usa rutas relativas.
- El catálogo ampliado rechaza métricas de otro dataset o entorno.
- SHAP explica los estimadores exportados, no RandomForest sustitutos. Registra
  hash de cada modelo y explica hasta 200 muestras por dominio.
- El dashboard usa los resultados nuevos y comprueba su procedencia. Las
  estadísticas de tests y balance CIPW son controles técnicos, no una medida
  conjunta de fiabilidad geológica.
- GeoNormPy necesitaba un ajuste mínimo de empaquetado: setuptools >=77 y
  eliminar el clasificador de licencia obsoleto, manteniendo GPL-3.0-or-later.
  Su mínimo de Python se ajusta a 3.9, compatible con ese backend de construcción.

## Validación ejecutada

Entorno independiente de Python 3.11, con dependencias exactas registradas en
`constraints-py311.txt`. La instalación de ambos proyectos y `pip check` pasan.
La suite local completó **26 pruebas correctas**.
Se comprobaron limpieza, cruces espaciales, particiones, ROC binaria,
serialización de RandomForest/SVM/XGBoost, esquema de exportación y fallos de
entrada. El código de `src/`, `scripts/` y `tests/` pasa Ruff.

La validación real reservó 528 muestras (336 VOL y 192 PLU) y utilizó las
2.123 restantes para CV por grupos de cinco pliegues. Los algoritmos eran los
dos baselines preexistentes; no se ajustaron para maximizar este holdout.

| Modelo / dominio | Exactitud CV | Exactitud holdout | F1 macro holdout |
| --- | ---: | ---: | ---: |
| XGBoost / volcánico | 77,97 % | 77,38 % | 0,5491 |
| RandomForest / plutónico | 55,48 % | 56,77 % | 0,4034 |

El modelo plutónico sigue siendo limitado. La depuración corrige la evaluación,
no garantiza una mejora de sus puntuaciones. El holdout tampoco es evidencia
de transferencia geográfica: faltan validación espacial y datos externos.
Los modelos finales exportados se reajustan con el dataset limpio completo;
las métricas del holdout corresponden al ajuste de validación anterior, no a
evaluar esos modelos finales sobre sus propios datos de entrenamiento.

Resultados completos: `artifacts/validation/baseline_validation.json`,
predicciones del holdout, matrices de confusión y curvas ROC. Exportaciones
nuevas: `artifacts/official_models/` y `artifacts/petropyqapf_transfer/`.
No se reemplazaron los modelos ni el instalador existentes de PetroPyQAPF.
No se ejecutó de nuevo la campaña completa de todos los modelos y conjuntos
de variables, ni el cruce sobre los shapefiles regionales completos; se
validaron los dos baselines reales y el cruce con solapamientos reproducibles.

Referencias de comportamiento: [validación por grupos de scikit-learn](https://scikit-learn.org/stable/modules/cross_validation.html),
[compatibilidad de modelos serializados](https://scikit-learn.org/stable/model_persistence.html)
y [cruces espaciales de GeoPandas](https://geopandas.org/en/stable/docs/reference/api/geopandas.sjoin.html).
